# Scientific design review

Read the parent research contract for the exact estimand and policy definitions. The recommendations below preserve its causal interpretation while identifying where implementation choices could undermine it.

## Constructs that must remain distinct

- A runtime execution graph, an evidential support graph, and a model's hidden reasoning are different objects. Only observable support adequacy is measured here.
- A minimal sufficient support set can contain multiple facts. “Unique support” does not mean one incoming edge, and alternative support may be an OR of AND-sets.
- A still-true existential conclusion does not validate a concrete action argument tied to a superseded witness.
- Fact correction is not permission revocation. Surviving evidence cannot restore revoked authority.
- A pending-action revision is not reversal of an irreversible external side effect. The main experiment corrects before execution; limit real-world rollback claims accordingly.

## Identification and analysis

The primary contrast is the difference in E-versus-R performance between bound and unbound actions within the alternative-support condition, averaged over base worlds. Unique-support cells supply negative controls and a secondary interaction. Preserve this distinction; a general comparison of framework success rates would answer a different question.

Policy branches within a structural variant share a realized prefix. Different structural variants have their own prefixes. Cluster uncertainty and resampling by base world; do not count every policy branch as an independent observation. Preserve all-prefix primary analysis, with correct-prefix analysis secondary and validity measured before treatment.

The primary outcome includes protocol-valid correct completion without an invalid attempt or applied effect within the allowance. A safety gate blocking an invalid action does not erase the attempted error. Store attempts and effects independently.

## Confounds to prevent

| Risk | Required treatment |
|---|---|
| Oracle labels become replacement answers | Exact controls reveal only their specified repair information. Verify no hidden state, task answer, or corrective action leaks into agent-visible inputs. |
| Recovery policy gets extra reasoning via automatic retries | Account for all calls; use the same declared caps and retry rules. |
| Framework state merge preserves obsolete fields | Test version replacement and deletion semantics; inspect actual action arguments and source versions. |
| Parser enforcement determines success | Separate schema validity from semantic correctness and report both. |
| Local reasoning failures dominate | Apply the inherited local/single capability gates before organizational interpretation. |
| Easy explicit evidence yields ceiling | Treat a bounded negative result as useful; pivot only through a declared new design and pilot. |
| Difficulty selected after outcomes | Fix generators/seeds and exclusions before confirmation; never regenerate until agents succeed. |

## Scope limitations to say explicitly

Complete evidence delivery and reliable ordered messages isolate integration and repair. They do not test communication loss, adversarial deception, open-world truth, or general decentralized coordination. Separate contexts and write ownership constitute the team setting, but a fresh full-information single-agent control does not identify the causal effect of decentralization.

Fixed recovery slots enable comparison of state interventions. They do not establish fewer model calls from adaptive scheduling. Preservation may still matter through correctness or retained work; measure it directly.

The bounded semantics permit a deterministic solution. An LLM extractor is an object of measurement of natural handoffs, not a necessary solver. Explain this to avoid framing an avoidable symbolic problem as a model capability breakthrough.

The fast support evaluator covers bounded monotone/unate cases. Arbitrary Boolean or numeric transfer semantics require their own independently validated evaluator. A controlled MasDrift-derived extension must not be reported as an official native benchmark score.

## Evidence needed for a useful result

Retain actual trajectories, source versions, estimated versus gold support, repair masks, invalid attempts, final actions, and control-job preservation. A few narrative examples cannot replace uncertainty estimates; aggregate accuracy alone cannot locate the proposed failure mechanism. Negative and null results should be interpretable under the same preregistered gates.
