# Research redirection

**Choose option 3:** substantially reframe recovery around revisable completion and search coverage, while preserving the core problem of correction after substantial distributed work. This is a recommendation for a subsequent specification revision; `PROJECT_SPECIFICATION.md` has not been changed.

## What survives

- Four peer agents, private information, controlled communication and exact evaluators.
- Shared prefix checkpoints with isolated sibling continuations.
- Authoritative current source records separated from derived agent state.
- No-change and answer-preserving controls, failed-prefix inclusion and world-level inference.
- Correction delivery made explicit and reproducible.
- Measured hardware/capability admission, Qwen3.5 preference and the 30 aggregate GPU-hour ceiling.
- The original source-retention/reset contrast as a strong baseline and fallback study.

## What changes

The primary question becomes whether recovery must revoke a team's conclusion that its work is complete, separately from correcting the objects it has already produced. Add events that create useful new opportunities: relaxed requirements, inserted options and added graph shortcuts. Current downward edits and deletions emphasize repairing bad existing answers; they do not cover this dimension adequately.

Replace the six-family main inference matrix with three search-relevant structural families and one small independent finite-search adapter. All 30 original task definitions remain understood and documented; benchmark breadth need not dictate the causal design.

Replace the primary reset interaction with the paired effect of reopening versus a fresh planner given the same acquired evidence. Retain the sham interaction as a key secondary check. Source delivery becomes common across policies; a separate dissemination experiment becomes secondary.

## What is added

1. Automatic root and child completion obligations, current objective/domain versions, and explicit unknown scope.
2. A wrapper for query/subtask receipts and a context renderer that distinguishes retained work from old completion claims.
3. A conservative reopening policy and a control/membership-aware reference policy.
4. Tool-mediated acquisition and exact offline measures of newly necessary work, false completion and repeated acquisition.
5. CPU conformance cases for delayed old completion, missing notes, domain insertion and consecutive revisions.

Selective scope is optional. Start with broad reopening. Add it only if runtime information can establish useful independence without an oracle and the broad baseline leaves meaningful cost to save.

## What is removed or deferred

- No semantic dependency graph extractor, support antichain, new provenance algebra or min-cut optimizer.
- No learned confidence calibrator, extra reviewer LLM, training or second-model campaign.
- No broad asynchronous runtime, KV-cache unlearning or irreversible-action compensation implementation.
- No claim that task-level “done” or a current receipt proves unrestricted semantic completeness.
- No production-scale efficiency claim from synthetic costs or small finite tasks.

LangGraph can remain a checkpoint substrate if its small integration is already useful. A Python loop is also sufficient. The framework must not define which answer or search region is relevant. This research phase writes no agent-framework code and does not lock new dependencies.

## Suggested sequence for more than one month

| Phase | Deliverable / decision |
|---|---|
| First implementation week | Independent generators, exact offline evaluators, task/receipt lifecycle and mock-agent isolation tests. |
| Second week | Private search adapter, natural-prefix pilot, current-information capability checks and measured inference forecast. |
| Following 1–2 weeks | Finish strong baseline adapters, freeze event generation/arms/analysis, execute only the admitted main schedule. |
| Remaining time | Analysis from raw artifacts, independent transfer, error taxonomy, reproducibility and writing. |

These are effort bands, not a deadline supplied by the user. Integration or hardware problems can consume the margin. Do not spend the inference budget debugging semantics that can be checked on CPU.

## Contribution packaging

The deliverable should contain a reusable completion-state interface, a small reference implementation, exact correction/search workloads, matched-prefix intervention records and an empirical account of when the interface matters. Explicitly attribute the state-management primitives to existing systems work.

Distinguish three outcomes:

- **Benchmark extension:** revisions and opportunity changes in SILO-derived tasks.
- **Empirical finding:** when stale stopping decisions survive current evidence, and which interventions repair them.
- **Reusable mechanism:** completion obligations whose lifetime is separate from retained artifacts, with conservative fallback under unknown scope.

Only the second is necessarily a new scientific result after execution. The third is presently a useful engineering synthesis with close prior art, not an established novel algorithm.

## Fallback decision

If natural omitted-work failures do not appear, fresh planning suffices, or the mechanism cannot be implemented without oracle scopes, retain the current controlled retention study and frame it as a careful generalization. If REVISE-style instrumentation subsumes the mechanism, use it and report the application-level lesson. Do not add complexity merely to preserve a novelty narrative.
