# Open research gaps

Status: research synthesis, 2026-09-30. These are bounded opportunities after the searches recorded in `landscape/`, not a claim of exhaustive coverage.

## 1. Recovery of omitted work, not only invalid existing work

The strongest opportunity is to separate **validity of retained objects** from **validity of treating a question as settled**. A supplier remains eligible after a budget increase, but newly affordable suppliers have not been examined. Old graph paths remain traversable after an edge is added, but may cease to be shortest. Old test results remain accurate descriptions of tests run, but a new requirement may require additional tests.

An artifact-only validation pass can correctly accept every checked object and still leave the decision inadequately supported. The missing object is a current justification for the search boundary, exclusion, or stopping decision. This does not defeat a complete dependency system: [REVISE](https://arxiv.org/html/2609.00643v1) already represents control and membership reads. The practical question is whether an ordinary agent runtime can expose and refresh useful completion obligations when those decisions occurred in opaque reasoning and were never recorded reliably.

**Potential contribution:** an automatically maintained completion lifecycle, with conservative reopening under uncertain scope, and a causal study of omitted-work recovery. **Unresolved:** whether this improves on a fresh planner or simply specializes existing workflow recovery. This is the leading direction.

## 2. What justifies reuse when historical dependencies are unknown?

Historical independence and current semantic validity are not equivalent. A result created using an obsolete premise may satisfy its current contract; another result can have current metadata and still be wrong. There are two legitimate routes: establish that its relevant inputs did not change, or establish its present validity independently. [Certifying algorithms](https://people.mpi-inf.mpg.de/~mehlhorn/ftp/master-final.pdf) already provide the second principle.

**Opportunity:** measure the cost/coverage frontier of practical checks in opaque collaboration. **Why secondary:** a strong checker on tiny SILO tasks can implement the entire solver; incomplete tests do not guarantee semantic correctness. Generic checked republication is also close to [MemoRepair](https://arxiv.org/html/2605.07242v1). This is a useful comparison, not the recommended core invention.

## 3. Recovery scope that degrades honestly with missing metadata

Fail-open selective invalidation misses consequences; conservative full-context exposure can taint almost everything. The unresolved engineering question is how much useful specificity can be obtained without pretending model citations are complete. Scope hints could prioritize work while automatic parent/root obligations provide a fallback.

The baseline must be **always use the fallback**. If broad reopening performs equally well, the scientifically useful conclusion is that semantic scope extraction was unnecessary. [StateAuditor](https://arxiv.org/html/2608.01619v1) and uncertainty-aware rollback already make blanket claims about unexplored implicit dependencies or uncertainty untenable; see the focused notes.

## 4. Recovery economics with expensive acquisition and imperfect stopping

Repeated inference is only one cost. Recovery may duplicate search, tool work, coordination and evidence acquisition. It can also silently stop with a feasible but obsolete decision. The meaningful frontier relates current-task quality, unjustified completion, acquisition cost and total work. [Reclaim Evaluation](https://arxiv.org/html/2606.25449v1) already studies source retention and its limits; simply showing that keeping sources helps would be a generalization.

**Opportunity:** identify when preserving coverage and assignment state saves work, versus when maintaining it costs more than restarting. **Boundary:** assigning synthetic prices to operations is a sensitivity analysis, not measured hours-long agent savings.

## 5. Composition across agents and revisions

Each peer may have an individually sensible answer while the team mixes objective versions, overlooks an unassigned scope, or accepts a delayed old completion. Existing epochs, snapshots and commit validation address much of this. The useful test here is whether the proposed completion interface composes with those mechanisms, not whether it reinvents them.

Two consecutive revisions and one delayed-completion test are inexpensive CPU conformance checks. A large asynchronous serving study is outside this project's compute budget.

## Crowded or already established claims

Do not build the contribution around discovering that stale derived work survives fact replacement; deleting a source is insufficient; dependency incompleteness is harmful; alternate support should be preserved; old worker messages need fencing; current evidence can conflict with old plans; or validation should precede publication. Each has direct predecessors documented in the landscape.

## The deepest remaining weakness, stated carefully

For this project, the most consequential boundary is **the mismatch between what a runtime can observe and what it needs to know to declare recovery complete**. A trace records work that happened. It does not automatically establish which unperformed work has become necessary. No finite completion record guarantees unrestricted search adequacy. A useful contribution must expose this uncertainty and make it operational, rather than promise to infer an invisible complete reasoning graph.
