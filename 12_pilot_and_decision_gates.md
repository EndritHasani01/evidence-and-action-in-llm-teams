# Pilot, capability gates, and decisions

The pilot exists to decide whether the scientific experiment is identifiable and affordable. It is not a small contest that E must win. Pilot worlds use a disjoint seed namespace and never enter confirmatory estimates.

## Gate 0: novelty before GPU confirmation

Read the unavailable full text of the current rollback-family submission and the most recent REVISE/MemTX versions through an ordinary accessible primary route. Compare their actual experiments against the action-binding × alternative-support interaction and O/OC/ON/OR interventions. Record a signed-off novelty paragraph with dates and versions. If the exact explanatory experiment is already established, use the replication/pivot rule in 03. Do not substitute a renamed architecture for a new contribution.

This gate does not block implementing the symbolic core or pilot. It blocks an unsupported novelty claim and expensive confirmatory execution.

## Expanded pilot: 476 primary-model calls, up to 16 second-model probes

Expand to 4 base worlds (2 per family),16 variants. Reuse the initial pilot prefixes and arms where requests are identical. Core total after expansion: 32 local probes +16 single calls +48 prefix calls +16 extraction calls +336 recovery calls across N/R/E/O/OC/ON/OR =448. Add 8 calls for two B reviewer-plus-recovery branches on existing pilot prefixes, and 20 calls for two disjoint transfer pilot variants (each 3 prefix +1 extraction +R/E × 3). This profiles the longer reviewer and transfer contexts, totaling 476 primary-model calls. Add at most 16 local/full-information probes on the 7B checkpoint only if Matrix A is otherwise feasible. The maximum funded pilot is 492 calls, within a hard 2 aggregate GPU-hour allowance; stop before exceeding it. Setup/reserve remains separately budgeted.

Four base worlds cannot estimate a population effect reliably. Do not use their effect size to promise power. Use them to expose missing architecture, floor/ceiling effects, cost and plausible variance, then run CPU power simulations over a range of variances/correlations.

## Capability and measurement gates

| Gate | Pass requirement | Failure response |
|---|---|---|
| Symbolic correctness | 100% agreement on enumerated support tests; independent task grader agrees on all generated pilot worlds; transfer numeric cases pass finite-domain cross-checks before transfer inference | Fix evaluator/generator; do not interpret any LLM result. |
| Source delivery | 100% required capsules and IDs delivered at the designated cut | Fix transport; missing evidence is not the chosen question. |
| Parse validity |≥ 98% schema-valid calls, counting truncation as invalid | Compress prompts/aliases or adjust output shape during development; reprice caps. Do not hide failures behind retries. |
| Local ability | At least 31/32 local probes correct | Simplify the local arithmetic/string task without removing the support/binding structure, or test 7B and reprice. |
| Centralized ability | At least 15/16 single-agent decisions correct | Local competence is inadequate for an organizational interpretation. |
| Prefix quality | At least 13/16 complete correct prefixes; at least 3/4 in each structural cell | Diagnose role/format/capacity bottleneck; revise and regenerate the development pilot. |
| Semantic opportunity | Both survival and invalidation cases exist by gold; all action/support cells populated; ≥ 1 meaningful natural extraction/scope error or residual behavioral error across pilot | If none occur, consider the ceiling rule below rather than injecting arbitrary errors. |
| Oracle nontriviality | O can still fail through new model outputs; evaluator does not gate semantic truth | If O is hard-coded to succeed, redesign the runtime. |
| Compute | Measured admission criterion in 10;2-hour pilot cap; memory≤ 14.5 GB per card | Serving changes before registration, Matrix B if sufficient, otherwise revise or stop. |
| Precision | Power/CI-width simulations make a scientifically material interaction test plausible; target primary half-width≤ 0.20 | Reframe around a better-powered mechanism contrast or seek more compute; do not claim a precise moderate interaction. |

The count thresholds are pragmatic capability gates, not high-confidence population claims. Report their uncertainty and outcomes in the thesis.

## Continue, pivot, or abandon

**Continue with the proposed study** if semantic/engineering gates pass, local capability is strong, natural scope or repair errors are observable, the corrected-versus-preserved distinction is nondegenerate, and the full paired matrix is admitted. E may lose the pilot; that is not a failure condition.

**Continue as a bounded negative study** if all feasible policies behave well, support estimation has observable variation, and the registered sample can exclude a material failure rate/interaction. Say the compact explicit protocol may be sufficient in this regime. Do not manufacture failures to save the original narrative.

**Pivot before confirmation** if the task is at ceiling with no measurable provenance or state errors. A permissible pivot is a longer ownership handoff or a more consequential action binding, while keeping local tasks easy and repricing every call. This requires a new design version, pilot and analysis contract. Synthetic deletion of selected edges remains a calibration tool; it cannot become the entire scientific story unnoticed.

**Pivot to representation evaluation** if action recovery succeeds but natural support sets are systematically wrong: study whether operational outcomes are robust despite poor provenance, and limit claims to observable support adequacy. This may be scientifically useful, but it is a changed thesis estimand and must be approved as a research choice before main data collection.

**Abandon this formulation** if close work already provides the same explanation and boundary conditions, symbolic labels cannot represent the intended action validity, 7B-level capability plus controls cannot fit compute, or the only positive result comes from a hand-crafted fault uniquely matched to the proposed fix. Preserve useful infrastructure and negative pilot results; do not turn them into a named framework paper.
