## Implementation checkpoint

The existing status CLI selects the saved declared main population (20 course,
60 thesis by default; nested thesis 40 remains explicit), validates regime and
supports a zoned `--as-of` clock. Analysis CLI adaptation remains M4. Missing
current workers remain unknown and are never created by status.

`CourseBudget` extends the existing saved budget binding with the 30/100-hour
ceilings and documented lower/upper prior bounds. Supplemental categories cover
only spending absent from supplied original worker ledgers; shared preparation
is course spending counted once overall, and other overall spending excludes it.
Smoke is a checked historical subset, never another cost sum. Every prior bound
defaults to unknown, including smoke; a verified zero needs evidence. Unknown,
unclassified or exceeded allocation/allowance withholds admission. Changing an
account, configuration, ceiling or prior bound cannot reset a saved worker run.

Main admission uses planned devices and matching measured phase/condition/device
records, unused reserves and one 25% margin, including future external overhead
once. Synthetic/unclassified CPU timing cannot supply a GPU forecast. The
independent allocation deadline conservatively protects remaining setup and
interruption allowances as well as the total ceiling; development also protects
its unused allowance. Reaching a deadline retains the original scope for a fresh
resource check. Timeout/termination/release allowance covers all assigned devices;
previous reservations remain charged even when admission is refused. No provider
starts for unknown prior spending or an unavailable main forecast.
