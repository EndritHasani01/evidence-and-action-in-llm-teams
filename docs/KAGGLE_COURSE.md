The controls cell normally stays unchanged: `ACTION="run_all"`, `SESSION_HOURS=10`,
and `RESUME_ZIP=None`. GPU mode is detected automatically. Run All on T4 x2 records
operator authorization for the fixed pinned-model stages and a conditional

The sequence is hardware stress/finite/cache checks, first 90 development slots,
the full five-world pilot, independent raw/effect audit and configuration freeze,
the fixed 20-world main matrix, then analysis and reports. Hardware acceptance
requires both complete-input probes with forced 256-token output and at least
1.5 GiB observed free headroom. Capability thresholds, complete-pilot 98% validity,
exact replay, persistence, all population/seed/protocol rules and missingness remain.
A failed scientific check produces an accurate limited result with retained evidence.

Progress reports stage, recorded/remaining slots, physical attempts, replay uses,
failures and unknown outcomes. Installation/download output streams live. Original
command logs, tracebacks, environment receipts, raw replies and checkpoints travel
in the resume bundle. Ten-minute quiescent backups and stage-completion exports
preserve finished calls without resampling them.

Before checkpoint download, every hardware request is constructed and the pinned
generation processors are checked on CPU. Diagnostic EOS is explicitly disabled
to force all 256 steps without triggering the numerical audit on EOS masking.
Quiet operations show a 15-second heartbeat. Verified cached environments and
checkpoint files are reused within the session; transient range-download failures
have bounded retries. The notebook measures temporary storage before installation
and retains path-specific free/required space and mount readings. Dependencies,
installer scratch and full pinned checkpoints use suitable session storage;
canonical workers, logs and exports stay in `/kaggle/working`. An interrupted
checkpoint download re-verifies and reuses its completed installation. Lost
temporary assets are rebuilt from pins in a later session. Failed setup logs remain
intact; an actually damaged installation can be rebuilt without duplicate venvs.
Neither a storage refusal nor an interrupted session switches models. Completed failures, adapter defects and failed scientific gates are never
automatically resampled. Source-compatible interrupted hardware stages resume their
original worker records; a saved report file alone does not determine completion.
