## 1. Selected experiment

Run **one fresh natural-prefix, paired retain/clear study under one fixed,
openly assisted agent environment**, with four feasibility pilots and twenty
held-out main worlds. Keep the existing maximum task, pinned model/runtime,
strict action semantics, three-call-per-agent limit and exact team scoring.

The question is:

> In this fixed assisted two-agent environment, how does retaining rather than
> clearing the naturally acquired visible history affect exact team recovery
> and effort after the specified withdrawal of the unique winning record?

The assistance package includes legal-action examples, explicit global-answer
and private-finality instructions, a short generic coordination strategy,
separated history/current-source/notice presentation, and public-rule-specific
rejection feedback. Supply the same package from the initial phase onward.
The agents still compute values, select and communicate evidence, decide when
to submit, and bear the consequences of their actual actions.

The primary target is the **total visible-history-policy contrast**. Useful
claims, wrong conclusions, feedback, conversational examples and context length
all move with the policy. That bundle is appropriate for this practical
question. A course report must describe this scope explicitly.

Do not add a controlled-history main arm, sham event, second model, repeated
sampling, prompt ablation, compulsory communication stage or memory architecture.
If the fixed candidate fails feasibility, complete the project as a bounded
feasibility investigation. No automatic rescue study is selected.

## 2. Why this resolves the competing recommendations

The [independent audit](../validation/i01-course-7-independent-scientific-audit.md)
establishes complete execution with weak collaboration: only 3/20 original
teams were correct, retain and clear each succeeded on 2/20 main worlds, and
60/206 team calls were illegal despite well-formed JSON and field types.
Main revised scalar controls succeeded on 15/20. The two discordant pairs went
in opposite directions. A read-only check of the canonical stores in this
finalization reproduced these headline counts and inspected the three calls
below; a new complete forensic audit was unnecessary.

| Direct evidence | Design consequence |
|---|---|
| `main-01/prefix/agent-1/invocation-0`: correct local 910 inside a rejected message-plus-wait action | Clarify action alternatives and rejection feedback while preserving strict effects |
| `main-08/clear/agent-1/invocation-0`: empty history, yet notice record 2 becomes a claimed partner submission | Separate environment metadata from peer reports; history alone cannot explain this failure |
| `main-04/retain/agent-0/invocation-1`: prose recognizes global 959, but the final submission is local 943 | Explain the global endpoint and finality; judge the committed action |
| Retain repeats the withdrawn answer in ten worlds, while clear lacks that value in current sources/history | Keep obsolete-answer repetition descriptive and accompany it with exact recovery |
| Device and physical sibling order are coupled in Course-7 | Save a counterbalanced schedule for the new cohort |

These records are in the [canonical checkpoint](../../notebooks/run/course-7-working/latest/).
The audit found no scorer, delivery or sibling-isolation defect explaining the
poor outcomes. It leaves numerical equivalence to an independent runtime
unverified. Accordingly, this design preserves the current runtime and its
health checks without attributing the failures to numerical corruption.

The three research stages answer different questions:

| Prior direction | Final disposition | Reason |
|---|---|---|
| [Initial quality proposal](../proposals/i01-course-7-experimental-quality-improvement.md): clarify the environment, establish usability, evaluate a practical policy contrast | **Retain the scientific target** | Closest to the course question and current implementation |
| [Fifteen-paper recommendations](../proposals/i01-course-7-literature-informed-recommendations.md): fixed evidence, conclusion present/absent, edit/sham | **Defer the new main regime** | Better identification of conclusion exposure, but changes history, population and estimand; that mechanism is outside the selected course claim |
| [Practical investigation](../implementation-research/i01-course-practical-literature-investigation.md): disclose a short strategy and use live pilots | **Adopt the direction** | Algorithm discovery is not the research target; supplied strategy can improve usability while preserving autonomous execution |
| Compare clarification alone against clarification plus strategy | **Do not add the arm** | Its marginal effect is not a selected endpoint; one disclosed package is sufficient |
| Guarantee competent histories or screen successful main prefixes | **Reject for this campaign** | Would change the natural all-world population and add selection cost |
| Larger model, thinking, constrained decoding, reflection or extra turns | **Defer** | Each adds a new behavioral/runtime condition without resolving all observed failures |
| Rich provenance, selective repair or an LLM failure judge | **Exclude** | Unnecessary complexity and supervision for an exactly scored two-agent task |

The controlled-history proposal remains scientifically coherent. Its advantage
is identification of another effect, rather than universal superiority over a
natural study. Choosing a narrower practical claim is the substantive resolution
of the apparent disagreement between the reviews.

owner-only. Both policies get the same current-source and notice rules.

Retain keeps literal own legal actions/submissions, delivered peer messages and

visible history. Both reset phase turns, waiting and submissions. Rejected raw
outputs remain audit evidence; they do not enter a peer's history as actions.
Earlier/current phase wrappers use the annex's two history-length boundaries,
without rewriting message contents or certifying claims.

**Clarification:** excluding a host-supplied before-value does not remove that
integer from a retained, lawfully visible old message or submission. Such old
content is an intended part of retain. No semantic filtering is permitted.

Keep whole-output strict parsing, duplicate-key rejection, exact fields/types,
private finality, message-before-finish effects, waking only on delivery, and
deadlock/horizon termination. Invalid replies consume their turn and deliver
nothing. Specific feedback describes the violated public rule and supplies no
answer-dependent warning, repaired action, retry or additional turn.

The assistance recommends adequate information before commitment while allowing
reuse. A correct old report from the unchanged peer can still be useful to the
changed owner. Mandatory fresh exchange would restrict that potential benefit.
Every peer must retain the freedom to choose its actual messages and timing.

## 5. Bounded budget and execution decision

| First-attempt stage | Maximum physical calls |
|---|---:|
| Six state checks and two full envelopes | 8 |
| Four qualification worlds × original/revised scalar control | 8 |
| Four single-call diagnostics | 4 |
| Four pilots × `(6 prefix + 6 retain + 6 clear + 2 controls)` | 80 |
| Twenty main worlds × `(6 prefix + 6 retain + 6 clear + 1 control)` | 380 |
| **Ordinary maximum** | **480** |
| Eligible interruption/requalification contingency | **20** |
| **Whole independent campaign ceiling** | **500** |

These stage caps and the total/reserve apply together. Shorter episodes save
spending without enlarging another stage, adding examples or creating a second
candidate. Diagnostics, warmups, failures and eligible retries are counted.
Loads and downloads consume time even though they are not inference attempts.

One identical infrastructure retry is permitted only without a durable outcome
and after confirmed prior termination. Wrong, invalid, truncated or recorded
timeout outcomes never retry. Preserve unresolved spending as an admission
block. A new load of the unchanged frozen runtime needs six current-load state
checks plus two envelopes, charged to contingency. Accepted qualification,
diagnostic and pilot outcomes remain saved. At most two eight-call reload cycles
fit the reserve, leaving at most four other reserve attempts.

Use the existing two stores and single serialized admission owner. A new
independent campaign needs separate explicit execution authorization; a new
directory cannot reset an existing campaign. Course-7 spending/outcomes remain
historical and are neither imported nor erased.

Use the exact [annex §4.3 forecast](i01-course-final-design-protocol-and-acceptance.md#43-conservative-resource-forecast),
including remaining pilot/main worst-case slots, the observed maximum ordinary
call time plus margin, measured export overhead and the export reserve. Known
call/export measurements, sufficient remaining stage/total allowance and actual
deadline margin are required. Preserve per-dispatch timeout/cleanup/export
guards. The serial forecast is deliberately conservative despite two devices;
it remains a heuristic. The 700-minute session window is only an operator
planning estimate. Reruns cannot extend a fixed deadline or invent provider
allowance. No duration or utilization guarantee follows from Course-7.

### Stages and exact eligibility

1. **CPU preparation after approval:** scoped adoption, implementation, saved
   inputs and deterministic acceptance evidence. No GPU work follows merely
   from these checks passing.
2. **Preparation after separate execution authorization:** actual-host/source
   checks, six A/B/A calls, eight scalar controls and two envelopes. All eight
   scalar controls must be legal and durably committed; accuracy is reported.
   A recorded format failure ends this prespecified qualification screen.
3. **Diagnostics:** run D00…D03 exactly once as specified in
   [annex §5](i01-course-final-design-protocol-and-acceptance.md#5-four-diagnostic-fixtures).
   Require settled durable evidence, then a verified quiescent checkpoint and
   an initial measured export time. Ordinary diagnostic failure has no extra
   numerical veto.
4. **Four pilots:** execute each complete natural prefix, retain, clear and two
   controls once, in index order. Complete all four despite ordinary wrong or
   illegal actions. Health, integrity, unresolved spending or resource faults
   can stop execution and leave explicit unknowns.
5. **One feasibility decision:** main is eligible exactly when all four pilot
   scopes have settled terminal/committed evidence and valid accounting/exports;
   at least **3/4 original teams** succeed; at least **7/8 pilot scalar controls**
   succeed; and current health/resources fit the remaining fixed main scope.
6. **Main:** if eligible and covered by execution authorization, run all twenty
   saved worlds in ten fixed batches. Ordinary main failure does not stop
   subsequent worlds, replace a prefix or change analysis eligibility.

The 3/4 and 7/8 cutoffs are prospective **course-usefulness choices**. Four
pilots cannot establish population reliability. Balancing owner/first cells
makes 3/4 stricter than always committing the first speaker's local maximum,
which can succeed only in the two original-winner-equals-first cells. It still
does not prove a particular reasoning process. The two scalar observations in
a pilot share an input pair and must not be presented as independent worlds.

There is no all-pilot-actions-legal condition, recovery-success threshold,
effect-direction requirement, message-style judgment or qualitative veto after
the objective rule passes. Trace inspection informs interpretation. A failed
rule yields a complete feasibility report with main **unexecuted/unknown**;
threshold relaxation, repeated pilot cohorts, model switching and prompt tuning
are outside this campaign.

**Diagnostic interpretation is narrow.** D00 and D03 ask an explicit action or
local query. D01 and D02 supply good historical reports. Their pass predicates
record whether the particular requested/target action occurred in one call.
For D01/D02, a legal message-only action may reflect a conservative strategy;
failure to submit immediately is a probe nonpass, not proof of inability to
aggregate or update. Report the actual action and this limitation. No diagnostic
aggregate score substitutes for complete live pilots.

Every pilot and main batch ends with inspection/export; periodic checkpoints
and settled-error exports remain enabled. Repeating a completed finite stage
spends zero and advances no other stage. Keep weights resident through the
authorized work and reporting, then close after final settled export. Report
actual process-closure acknowledgements; provider deallocation and successful
external download require separate observations.

## 6. Outcomes, uncertainty and interpretation

For each intended main world, let R and C be exact terminal both-agent success
under retain and clear. Known wrong submissions and terminal noncompletion
are zero. Unexecuted, unresolved or unavailable episode evidence is unknown.

```text
D_w = C_w - R_w
delta = (sum over all 20 intended worlds of D_w) / 20
```

Positive delta favors clear. Display each arm's exact success count and the
four paired categories: both, retain-only, clear-only, neither. Include unknown
coverage separately. Keep the world as the analysis unit and preserve sibling
dependence. Avoid agent/call-level independent-sample tests.

**Clarification of uncertainty:** with complete records, delta is known exactly
for the realized twenty-world, fixed-seed cohort. The exploratory bootstrap
describes empirical world-resampling variation for the broader equal-stratum
generator interpretation. It does not measure uncertainty about that observed
arithmetic, repeat-generation reliability on a fixed world, or all possible
model seeds. Its small-sample nominal coverage is unestablished here.

Use the annex's fixed 10,000-draw stratified paired bootstrap: five draws per
owner/first stratum, prescribed ordering, seeded `choice` sampling and sorted
zero-based elements 250/9750. No interpolation or post-result method selection.
Show constant-stratum and zero-width warnings, including all-success cases.
Do not claim equivalence, a significant null or adequate power for modest effects.
No primary p-value is selected.

If a required pair is unknown, the primary twenty-world point estimate and
interval are unavailable. Compute the sharp completion bounds by allowing each
unknown binary outcome to be 0 or 1, with the denominator fixed at twenty.
Those bounds express missing evidence. They are not sampling intervals.
Any complete-case summary has its own explicit denominator and status.

The principal secondary endpoint is the paired mean
`clear ready-model seconds − retain ready-model seconds`. Include all attempts,
including unsuccessful episodes and failed actions. Unknown time stays unknown;
an intended-cohort effort contrast/interval requires every pair's complete
effort. Show observed cost coverage, calls/tokens and outcome together. Do not
turn fast wrong finalization into useful-work efficiency or use an accuracy/cost
composite. Prefix cost is paid once physically and charged to both hypothetical
end-to-end policies logically; controls/diagnostics are physical research cost.

Required additional displays are:

- Original-team and scalar correctness, with actual denominators; correct-prefix
  recovery counts only, with no subgroup interval or additional hypothesis test.
- JSON validity, field-schema validity and action legality separately, by phase;
  episodes affected, terminal reasons and unknown coverage.
- Both-submitted completion, agreement and wrong agreement; locally refutable
  submissions over forty intended agent slots per policy, with submission coverage.
- Obsolete-answer repetition in submissions/worlds, with its unequal old-value
  availability caveat; literal copying alone is not a failure criterion.
- The annex's six-category, lowest-index, trace-linked casebook. Human descriptions
  identify visible contradictions and ambiguity, with reviewer status disclosed.

Preserve Course-7's results and interval exactly and report it separately.
Cross-campaign differences cannot identify the assistance package's effect.
Scalar-versus-team differences do not identify a pure communication-failure
rate. Source availability, legal actions, consensus and fluent explanation each
have narrower meanings than exact success.

The allowed conclusion is a bounded effect or null for this assisted maximum
withdrawal environment. Pure memory, internal anchoring, revision specificity,
preservation of expensive work, general agent reliability and multi-agent
superiority remain outside the design. A floor or ceiling in main is reported
honestly; it is not an invitation to tune task difficulty or seek a policy winner.

## 8. Adoption boundary and completion

The selected differences from the current regime are the common assistance and
presentation/feedback; explicit public single-record rule; four qualification
worlds and four diagnostics; four balanced pilots and the fixed usefulness
decision; fresh seeds/inputs; decoupled assignment; revised 480+20 stage budget;
prospective owner conditioning; and the reporting conventions above. The
stricter whole-input overlap check is an additional release safeguard. All
other applicable §12 scientific invariants remain required.

| Category | Selected action |
|---|---|
| Engineering/reporting repair | Accurate derived legality/coverage labels and any demonstrated implementation defect; preserve raw outcomes and historical score |
| Behavioral intervention | One fixed assistance package, renderer and public-rule feedback; no claimed component efficacy |
| Experimental regime | Fresh natural-prefix assisted retain/clear study, bounded pilots/main and exact selected estimand |
| Contract amendment | Prospectively adopt the listed deltas in §12 and record the engineering handoff after approval |
| Actual research execution | Separate explicit authorization for the independent campaign and its bounded GPU stages |

The user's new-Markdown-only constraint is why the existing specification,
living plan, configuration, prompts and code are untouched. Approval can make
the design the basis of a scoped adoption and implementation task; it supplies
no implicit GPU or main-run authorization.

The course study has a legitimate endpoint in each of three cases: completed
feasibility with a failed prespecified gate; completed admitted twenty-world
evaluation; or an explicitly partial execution stopped by a real integrity or
resource fault. Each requires a reproducible report, intended-scope coverage,
reconciled accounting and verified portable export, with unknowns disclosed.
A partial run must remain labelled partial. No direction or magnitude of a
retain/clear effect is required for a useful course result.

**Decision for approval:** one openly assisted natural-policy campaign, with
four pilots, twenty held-out main worlds, the exact incorporated protocol and
the fixed stop rules above. Implementation and experimental execution remain
subsequent work.
