# Independent candidate analysis from protocol structure

Date: 2026-10-04. This review develops substantially different possibilities and deliberately retains failures. It does not select the final recommendation independently of the literature review.

## A. Historical transition evidence

**Principle.** A previous fact can be invalid as current state and still be valid historical evidence needed to update old computation. Distinguish current records from explicit version transitions.

**Question.** Does the relative value of retained reasoning change when peers receive an authoritative before/after transition instead of only the replacement? Can one small event record substitute for obsolete narrative while avoiding recomputation?

**Fit.** Stable records, versions, immutable prefixes, and exact tasks already exist in PS. No new task, model, reviewer, or hidden dependency parser is necessary. Preserve L/B/C/F main design and add a diagnostic payload contrast to B/C only if the measured budget permits.

**Evidence.** Executed prefix and sort witnesses show same retained candidate/current private evidence plus replacement can require different new outputs. An explicit before-value distinguishes those examples. Difference-array unchanged anchors refute a blanket insufficiency claim. Max/top-K/BFS remain ambiguous even under a complete edit record.

**Threats.** Database deltas, incremental view maintenance, old/new notification APIs, event sourcing, and sufficient-statistic updates are obvious direct precedents. This would be an empirical interface/boundary contribution, not a new delta algorithm. New agent papers may already compare old/new updates against overwrite; novelty depends on exact method review.

**Causal requirements.** Both matched policies receive the identical payload in each contrast. Historical values must be marked version 1 and absent from the current table. Runtime cannot apply task-specific delta algebra or reveal changed-output coordinates. Compare B versus C under replacement and under transition, not B-transition versus C-replacement. Report token/prompt changes honestly. A delta is additional information, so any benefit is information design; do not call it better reasoning. The interaction can still be explained by before-values allowing convenient arithmetic, which is precisely a useful mechanism if stated narrowly.

**Risks.** B may already remember the old value; C may not retain a candidate to update. An observed delta benefit restricted to B could show that the transition helps reuse computation but cannot resurrect discarded computation. No benefit might mean current evidence already suffices, model arithmetic is limiting, or the before-value is reconstructible. The pilot should inspect payload availability without selecting main edits on model failures.

**Cost.** Two additional 16-call branches on 12 predetermined worlds cost 384 calls, plus any new sham payload controls required by the exact claim. At an illustrative 15 allocated seconds/call that is 1.6 GPU-hours, not a forecast. Full 48-world B-delta/C-delta costs 1,536 calls, 6.4 illustrative GPU-hours, likely too expensive as an append-only study. Implementation is a typed event renderer and diagnostic accounting, estimated several days plus tests; actual time unmeasured.

**Negative result.** If explicit transitions add no benefit beyond current records, keep the simpler source-table contract. If gains appear only when old candidates are preserved, the result identifies the minimum useful retained representation rather than supporting blanket reset.

## B. Observable limits of selective retention

**Principle.** Without true semantic dependencies, runtime can conservatively bound potential historical influence from source exposure and time-ordered communication.

**Question.** After useful collaboration, does this safe observable information leave meaningful partial history to retain, or does selectivity collapse? Is exposure breadth informative about the retain/reset tradeoff after controlling descriptively for family and prefix competence?

**Fit.** All required events are already logged. The strongest initial contribution needs CPU analysis only. A temporal cut of derived objects is a possible later arm, not necessary to establish the descriptive boundary.

**Evidence.** Executed equal-static-graph schedules have different temporal cones. Fully connected per-round messaging saturates promptly; sparse legal schedules do not. Natural-prefix distribution is unmeasured.

**Threats.** Causal rollback, dynamic taint, information-flow labels, tracked-read selective replay, build dependencies, and “taint explosion” are close precedents. The graph construction is not new. Useful novelty would be measured saturation and the mismatch between possible causal influence and exact changed outputs in opaque collaborating LLMs.

**Causal requirements.** No exposure label equals semantic dependence. A partial cut must clear stale-influenced sender messages and recipients' later derived states, not only original source mentions. Histories must be rendered without dangling message structure. Source-ref selection itself can convey old-world control information; keeping current evidence prevents a global noninterference claim. Same-volume arbitrary/age-based pruning is the strongest explanation for any practical gain.

The modeled cone overapproximates dependencies carried by actual delivered contents and retained objects. It is not an unconditional bound on all causal channels: message absence can influence a recipient, and old state can determine whether, where, or which record is sent. Tracking all potential absence/control channels would require extra assumptions or broader invalidation. Any reported selectivity is conditional on this delivered-content model.

**Cost.** Offline descriptors add zero calls. A partial-cut arm on 12 changed plus 12 sham worlds costs 384 calls; one matched-volume control on the same events adds another 384. At 15 seconds/call total extra cost is 3.2 illustrative GPU-hours. Full matched arms are expensive. Several days for event-graph accounting; up to one or two weeks if testing general safe context cuts, which should therefore be avoided initially.

**Kill conditions.** Exposure measure nearly constant; no clean history remains; the graph misses prompt/history channels; pruning reduces to C; same-volume deletion matches it; or an existing paper already tests the same saturation/footprint relationship. Retain the zero-call diagnostic even if the algorithm arm dies.

## C. Typed prior answer versus conversational narrative

**Principle.** Separate computed output from its surrounding conversational history using the already-required candidate field.

**Question.** Is the reusable value of prior reasoning carried mostly by the candidate, while extra narrative contributes stale influence or distraction?

**Fit.** One exact state transform: C plus last valid pre-event own candidate, labeled historical, with no gold admission rule. No prefix extraction calls.

**Threats.** Answer-only memory, rationale stripping, structured summaries, state compression, and very recent correction papers are direct precedents. This is likely a baseline rather than a final innovative contribution.

**Identification.** Candidate helps can arise from shorter context or a privileged compact representation; these are intervention effects, not evidence of latent anchoring. A sham arm is needed. If candidate-only and B differ, the contrast includes old intermediate candidates, message prose, validation errors, and sender-selection metadata together. Do not claim a pure psychological narrative effect.

**Cost.** One changed/sham pair on 12 worlds = 384 calls; full 48 worlds = 1,536 calls. Renderer change is small, but a sufficient-statistic theory can become misleading if it assumes before-values or gold candidates unavailable in PS. CPU proofs explicitly caught these mistakes.

**Negative result.** If C already matches candidate retention, no extra compact memory is needed. If old candidates propagate pre-existing errors, report the dependence on pre-event competence without selecting correct prefixes for the primary result.

## D. Communication-free first-round correction capability

**Principle.** First recovery-round outputs are generated before any new peer message can arrive. Their success isolates what a peer can do immediately from retained local state and the event.

**Question.** Which policies restore correct affected coordinates in one call, and when does later communication add value?

**Fit.** Zero new runs. All four peers use immutable start-of-round views. This is a naturally clean temporal boundary already embedded in the protocol.

**Threats.** A first-round contrast is simply an endpoint of the already-planned trajectory, not a new algorithm or general communication lower bound. Peers may have complete information before correction, or derive correct values by chance.

**Identification.** Describe first-round success as observed immediate recoverability, not proof that no new communication is necessary in all worlds. Constructive ambiguity results can identify representation limits for selected exact views, but raw-evidence-only uncertainty cannot exclude useful prose in B.

**Cost/value.** Free and interpretable; deserves a planned secondary figure if a primary extension uses transition information. Insufficient alone for a major originality claim.

## E. Historic acquisition bias after a corrected cutoff

**Principle.** Fresh retained source values can still reflect obsolete decisions about what information was worth gathering.

**Question.** Do max/top-K recovery failures arise because relevant reserves were never delivered, even after every agent has the authoritative update? Can existing post-event acquisition traces distinguish this from stale copied numeric outputs?

**Fit.** Uses existing winner-lowering edits and source forwarding, with no completion lifecycle. It could preserve the useful insight from the previous branch while keeping all six families.

**Threats.** Negative provenance, selector/membership reads, search reopening, and dynamic optimality are established. Exact “needed record” labels can be oracle-like and prose may already communicate its value. A source table is not a complete model knowledge ledger.

**Identification.** Offline exact comparisons can show that the current raw-source view is insufficient, but cannot assert that the model lacked the information. An intervention equalizing fresh raw evidence would change information availability and may collapse into a full-information diagnostic. Do not design one without a clean question.

**Cost/value.** Low-cost descriptive analysis; difficult to promote beyond a narrower phenomenon without broadening the interface. Reject as a standalone mechanism unless a natural decisive divergence survives stronger controls.

## F. Partial peer resets and recovery externalities

**Principle.** A reset peer can be influenced again by an unreset teammate; recovery is a team intervention rather than four independent local decisions.

**Question.** Is resetting a subset superadditive or subadditive in team recovery? Does retained peer prose restore useful state or reintroduce stale conclusions?

**Fit.** Four peers allow all 16 reset masks conceptually, but do not run that matrix. One owner-only reset or an exposure-based mask could be a diagnostic.

**Threats.** Selective distributed rollback and causal cones cover the basic principle. A partial reset confounds reset amount, agent identity, private information, and output placement; strong controls consume several arms. A trace showing regression after a message is not causal attribution.

**Cost/rejection.** At 12 worlds, every extra mask costs 192 changed calls before shams. Testing meaningful interactions rapidly becomes larger than the main research question. Retain as future work unless the offline cone identifies an unusually decisive paired intervention.

## G. Reversible-change hysteresis

**Principle.** The same final source world reached through different truthful histories can induce different recovery behavior.

**Question.** Do agents converge to the same outcome when current information is identical but past answers differ?

**Fit.** Would be an unusually direct history-dependence test, but requires multiple prefixes or chained revisions, both excluded by PS's single-event matched design.

**Threats.** Belief revision and path-dependence studies already target similar effects. Different prefixes acquire different sources and produce different competence, making matched final-world comparisons difficult. Fixing those views can remove the distributed phenomenon.

**Cost/rejection.** Additional prefixes and multiple corrections consume calls and add design complexity. Lower priority than the payload and exposure additions, which use the existing single prefix.

## Comparative judgment at this stage

The most useful research direction from source inspection is not to add an elaborate semantic memory manager. There is a concrete unexploited distinction between **current evidence**, **historical transition evidence**, and **compressed computed output**, plus a measurable limit on how finely runtime can select historical work after collaboration. These provide falsifiable questions within PS.

None is certified novel here. Transition interfaces may be a valuable classical idea whose interaction with opaque peer state has not been measured in this setting; exposure may yield a stronger boundary finding than a new policy; answer-only retention is probably the strongest simple baseline. The prior completion recommendation has clearer operational machinery, but requires a new query/closure interface and faces an exact reduction to control-dependent invalidation. Structural fit alone therefore favors exhausting these PS-preserving alternatives before redirecting the thesis.
