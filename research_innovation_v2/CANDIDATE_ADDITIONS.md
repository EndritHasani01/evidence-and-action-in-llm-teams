# Candidate additions: comparison before recommendation

Investigation date: 2026-10-04. These candidates answer substantially different scientific questions. They were developed from the PS and the previous corpus, then challenged by primary-source searches, mathematical counterexamples and independent reviews. None has an executed LLM performance result. See [novelty adversary](NOVELTY_ADVERSARY.md) for the strongest reductions and [feasibility](FEASIBILITY_AND_VALUE.md) for the final budget.

## 1. Historical transition information × retention — selected focused addition

**Central insight and question.** Old input data can be obsolete as current facts yet useful as historical operands for updating accumulated work. Does explicitly supplying the before-value change the value of retaining collaborative history? This uses an existing runtime-owned record and the existing B/C intervention, so it belongs naturally to the PS.

**New knowledge.** A retention comparison can depend on its correction interface. The addition could identify when useful history needs transition information, when such information is redundant, or when temporal labels fail and old-value copying increases. The proposed contribution is the interaction and its boundaries, not a new receipt format.

**Prior work and novelty.** CDC, self-maintainable views, DBSP and StateAuditor already use relevant principles. CIR and correction-wording work require matched intervention/content controls. Novelty confidence is limited for a new empirical question and very low for an algorithm claim; absence of the exact factorial in inspected papers is not proof of priority.

**Assumptions and oracle risk.** Runtime has an authoritative archived v1 and actual v2. No dependency inference, exact-solver output or D/U labels enter the prompt. Old values may already be visible or reconstructible; classify that carefully. Revealing a former value to a previously unexposed peer is intentional additional historical information, not equal total information.

**Identification and evidence.** Add BΔ/CΔ only on all existing Prefix Sum/Sort worlds, preserving original B/C. Focus on the first recovery round before new peer messages, with four-round curves mandatory. Equal source tables, calls, caps and correction layout; record length and presentation limitations. Constructed identical-view/different-answer witnesses establish possibility, not prevalence.

**Cost/generalization.** 384/512 extra main calls plus 64 development calls; several focused implementation days. Applies conceptually to cached aggregates, reports, partial calculations and edits in distributed workflows, but no hours-long savings are established.

**Failure/rejection.** Before-values are redundant; useful summaries are absent; clearer wording explains the result; first-round benefits regress; or budget/power is inadequate. A useful null requires bounded uncertainty. If no live extension fits, preserve the original study and the CPU atlas.

## 2. A recovery-information atlas — selected supporting analysis

**Insight/question.** Output change size is different from what information a retained representation needs to update. Can two valid worlds produce the same visible retained state and update but require different new answers? This asks what reuse can achieve, before asking how an LLM performs it.

**New knowledge and fit.** It explains why a one-coordinate maximum can require new alternatives while many prefix coordinates can be updated by a small delta. The six task families are unusually useful for this comparison. Separate local from collective sufficiency, correct from incorrect summaries, historical operands from discarded alternatives, and current-evidence completeness from prompt length.

**Predecessors/novelty.** Exactly the logic of materialized-view self-maintainability and indistinguishability, with related agent local-view impossibilities in Commitment Hierarchies. Not a new mathematical theorem. Its value is a precise theory-to-measurement link for this benchmark and a safeguard against false interpretations.

**Assumptions/oracle boundary.** A proof must specify the retained view. Gold-correct old outputs may define an offline ideal case, but cannot be supplied or filtered into runtime state. Unrestricted prose defeats cheap exact full-prompt sufficiency classification; use provable cases and unresolved labels.

**Evidence and cost.** Executed 8,748 finite update checks, numeric/graph counterexamples, and two scripted full-B-state witnesses. Additional analysis uses CPU only, no model calls; a few implementation days to annotate real prompts. Generalizes to deciding what computation summaries omit.

**Negative value/rejection.** If every practical boundary reduces to full current evidence access, the atlas still prevents claiming a hidden semantic mechanism. Reject a standalone novelty claim if it merely restates known incremental equations without informing experiment or interpretation.

## 3. Conservative exposure and loss of selective-recovery opportunities — supporting analysis

**Insight/question.** Complete logs can still be too coarse to distinguish useful unaffected reasoning from exposed reasoning. How much derived state lies outside the corrected record's time-respecting exposure cone after real collaboration?

**Fit/capability.** The PS already logs source deliveries, messages and histories. A runtime can compute possible dependence without reading chain of thought or extracting semantic edges. It might decide that a selective filter would be identical to C before spending inference on it.

**Prior/novelty.** REVISE, rollback recovery, PlanFence, APPA, ESC-CR and NeuroTaint subsume the invalidation principle. Reliability/contagion and trace-divergence work threaten any generic propagation law. The possible contribution is measured applicability or a degeneration boundary on natural traces, not a new graph algorithm.

**Identification/oracle risk.** No hidden gold is needed for the cone. D is evaluator-only; exposed-call counts and changed-coordinate counts have different units and cannot form an over-invalidation ratio. Retained evidence membership may preserve old selection effects. No noninterference guarantee follows for the whole prompt.

**Evidence/cost.** CPU temporal-order counterexamples and routing enumeration are executed. Actual saturation/predictive value remain unmeasured. Zero extra calls for description; a selective-reset policy needs at least a matched-volume deletion baseline and possibly sham, at least 32–64 extra calls/world. Several days for analysis, more for causal controls.

**Negative result/generalization.** If cones saturate or observed reachability predicts nothing beyond simple variables, expensive provenance may be unnecessary at this granularity. This informs opaque workflow instrumentation beyond SILO. Reject a causal claim based only on trace correlations or deliberately dense toy schedules.

## 4. Retain only a typed result — credible simple policy, not selected

**Insight/question.** B and C are extremes. Can the last own candidate retain useful computation while omitting most stale discourse? It is an exact projection of already visible state and introduces no semantic classifier.

**Fit/new knowledge.** Identifies a possible minimal practical state representation. It separates preserving outputs from preserving conversation, though it still changes content and length together.

**Prior/novelty.** ICR's answer-only/full-text comparison and compressed working memory are close. Real source revision after multiple private-information rounds is a different regime, not a new representation principle.

**Assumptions/oracle risk.** Keep the actual candidate even when wrong; no oracle repair or correct-prefix selection. Keep only a peer's own already visible candidate, not all peers' candidates. Output representations differ radically in information content across tasks.

**Identification/evidence.** Compare K with B/C under change and sham, with identical current evidence and receipt convention. A result that K captures B's benefit cheaply would be useful, but candidate-only sufficiency proofs alone do not predict model performance.

**Cost/generalization/rejection.** 32 extra calls per chosen world for two events; roughly 2–4 implementation days. Applicable to plans and typed task results where such artifacts already exist. Reject as headline if equivalent to ordinary answer-only context, if wrong-candidate anchoring dominates, or if useful work resides in omitted intermediate summaries. Do not add it merely because it sits between B/C.

## 5. Partial-reset externalities — distinct distributed phenomenon, deferred

**Insight/question.** Clearing one peer may help that peer yet affect retained peers through new messages; retained peers may reintroduce obsolete conclusions to cleared peers. Are reset effects additive across the team?

**Fit/capability.** Four peers permit explicit reset masks between B and C with the same evidence and update. This directly exploits feedback absent from single-hop ICR.

**Prior/novelty.** Fault containment, distributed rollback/domino effects, interference experiments and contagion are precedents. The narrow behavioral interaction could be new in this regime; the existence of network externalities is not.

**Assumptions/causality.** Randomize or enumerate masks before outcomes; control reset count, owner status, source coverage and sham. A single owner-reset arm confounds identity/knowledge with selectivity. No gold-dependent masks or semantic reset choices.

**Evidence/cost.** No live evidence. Two extra masks cost 32 calls/world, or 64 with sham; a complete 16-mask matrix costs 224 extra changed calls/world beyond B/C, too large. One to two weeks of design/integration; current n cannot reliably estimate several interactions.

**Value/rejection.** A null could support whole-team policies as adequate; strong feedback would matter to real agent runtimes. Defer because few masks give ambiguous results and enough masks consume the study. Do not infer recontamination simply from equal old numeric answers.

## 6. Adaptive continuation versus reset — practical decision rule, rejected as core

**Insight/question.** Rather than B/C forever, retain briefly and reset when observable progress stalls. Inputs could be schema failures, repeated candidates or delivery status.

**Fit/new capability.** Makes an online recovery decision with no oracle. A fixed one-round delay is a strong simple baseline; a learned risk model must beat it.

**Prior/novelty.** CIR directly studies recovery routing; PoS uses persistence/stagnation and fallback. Restart theory needs assumptions such as recognizable success that do not hold here.

**Assumptions/oracle risk.** Agreement is not correctness. Runtime cannot use exact AUC, D/U, hidden gold, or an evaluator-based stop. Choosing thresholds on the main worlds leaks test outcomes.

**Identification/evidence.** Requires rate/cost-matched random or fixed schedules, held-out selection, and full call accounting. No calibrated signal has been demonstrated. Reusing branch outcomes offline is not a deployed-policy evaluation if the rule changes intermediate state.

**Cost/negative value.** One fixed schedule costs 16 calls/world, matched sham another 16; learned calibration requires additional independent data. One to two weeks plus inference. Useful negative finding: simple delivery/progress signals are inadequate. Reject as core because tens of clusters and new direct predecessors make novelty and calibration weak.

## 7. Validate and salvage artifacts — useful principle, rejected as main mechanism

**Insight/question.** Current validity can justify reuse even when historical dependence is unknown. Check retained results against present contracts, then keep those that pass.

**Fit/capability.** Preserves useful work without complete semantic lineage. The old branch's valid-path/not-shortest and feasible-choice/not-best counterexamples remain essential.

**Prior/novelty.** Certifying algorithms, checked publication, MemoRepair, REVISE and agentic repair branches already establish the principle.

**Assumptions/oracle risk.** For tiny prefix/sort/max tasks a sufficiently strong checker can compute the answer. A solver disguised as a validator would supply privileged computation. Weak checks establish feasibility or shape, not global optimality.

**Identification/evidence.** Give every baseline the same checker and charge its cost; include deterministic non-agent solving. Existing CPU counterexamples prove the weak-check problem, not benefits in real agent recovery.

**Cost/generalization/rejection.** Several contracts and fair baselines take roughly 1–3 weeks; 16–32 calls/world plus CPU validation. Generalizes where checking is genuinely cheaper than constructing. Reject here if checkers solve the benchmark or the method reduces to known validation with renamed objects.

## 8. Build change-resilient work before the edit — prevention dimension, deferred

**Insight/question.** Store parameterized procedures, frontier reserves, compartmentalized summaries or sufficient statistics before a future change, rather than trying to infer their dependencies afterward.

**Fit/new knowledge.** Could expose a prevention-versus-recovery tradeoff and explain why some histories remain reusable. It changes the prefix representation itself, so it is more disruptive than a boundary intervention.

**Prior/novelty.** Incremental computation, auxiliary materialized views, plan caching, hermetic builds and context isolation already provide the principle. Choosing a representation with advance knowledge of the actual edit would create an artificial advantage.

**Assumptions/identification.** Hide future edits, charge normal-task overhead, retain no-change prevention controls and assess initial competence. Compare with simply keeping more raw evidence. Parameterized executable code can turn the LLM task into ordinary deterministic programming.

**Evidence/cost.** No model evidence. New prefixes and controls require at least another matched prefix/continuation set, not a cheap extra arm; several weeks of adaptation. Multiple revisions may be needed to amortize preparation, outside the first study.

**Negative value/rejection.** If raw evidence retention gives equal benefit, custom representations are unnecessary. Potentially broad utility in long workflows, but defer because it changes what work existed before the correction and would weaken the clean original comparison.

## 9. Cyclic revision and path dependence — interesting alternative, deferred

**Insight/question.** Return an input to its original value after an intervening change. Does the team return to the same correct behavior, or retain damage from the path?

**Fit/capability.** Tests a failure of recovery that a one-change experiment cannot expose. Current input alone need not determine the state of an agent team.

**Prior/novelty.** Iterated belief revision, hysteresis and stateful control are mature; new affective-agent hysteresis papers use similar terms for different objects. The terminology alone adds nothing.

**Assumptions/identification.** Match total calls, notices, evidence acquisitions and output opportunities. A two-edit branch versus an untouched branch differs in many ways; the original matched prefix controls only the first boundary. No oracle-selected reversal or successful-prefix filtering.

**Cost/evidence.** At least two second-stage continuations add 32 calls/world, with more needed for balanced control histories. No executed LLM result. Several days to weeks for branch semantics and analysis; acquisition differences make interpretation difficult.

**Negative value/generalization.** Could show simple state replacement suffices or reveal recovery debt in repeated edits. Defer until one-change behavior is established; do not append revisions to manufacture complexity.

## 10. Error inheritance and fault-containment metrics — supporting, not novel headline

**Insight/question.** Distinguish failure to update a correct old result from correctly transporting an old error. Linear tasks admit a metamorphic delta relation; unaffected coordinates reveal collateral damage.

**Fit/new knowledge.** Uses before/after candidates already logged. Can clarify why a correct update operation still yields a wrong final answer and quantify temporary damage rather than only endpoint accuracy.

**Prior/novelty.** Metamorphic testing, incremental algorithms and self-stabilization already make related distinctions. The PS itself already measures repair/preservation trajectories; another summary statistic is insufficient invention.

**Assumptions/oracle risk.** Calculate offline; never give the valid delta transform or gold outputs to agents. A model matching a relation does not prove internal causal use of that relation. Nonlinear tasks do not share a universal transport function of the old answer.

**Cost/evidence.** CPU-only, one to several days; algebra verified for the small exhaustive probe. No additional inference. Generalizes to computational artifacts with known invariants.

**Rejection/negative value.** Keep only if it changes interpretation of observed failures. Do not inflate the report with multiple redundant metrics or claim exact task relations establish recovery competence.

## 11. Completion/search reopening — serious competitor, not selected

**Insight/question.** Existing work may remain valid while the decision to stop searching becomes invalid. This is the earlier branch's strongest contribution and its counterexamples survive.

**Fit/new capability.** Automatic root obligations and current query receipts could force reconsideration without discarding positive work. However, the PS already keeps all peers active; meaningful search closure needs new finite-query acquisition semantics and different events.

**Prior/novelty.** Dynamic CSP, LPA*, why-not/control provenance, REVISE and MemContinuum were known; TRACE, Commitment Hierarchies, GitHarness and PoS add nearby capabilities. Representing closure as a control node reduces much of the method to existing recovery.

**Assumptions/oracle risk.** Scope notes cannot certify hidden omissions. Current query receipts prove work occurred, not completeness. An exact query/coverage oracle can manufacture the desired effect.

**Identification/evidence.** Need artifact-identical generic reconsideration, matched refreshed observations and a control-aware baseline receiving the same new state. The earlier CPU examples prove logical possibility; natural omitted work and useful selectivity are not measured.

**Cost/generalization/negative value.** Historical plan totals 5,592/4,032 main calls by replacing the original matrix with fewer search-oriented families/worlds; weeks of adapter/lifecycle work. Strong transfer story for search/research/planning. If a simple fresh planner suffices, report it. It has not earned replacing the cleaner six-task correction study.

## Selection after the attacks

Choose **one focused experimental dimension**: transition information × retention, supported by the recovery-information atlas. Use exposure analysis only where it helps explain why more elaborate selectivity is unnecessary. Preserve candidate-only, adaptive schedules, partial-reset effects and completion as explicit alternatives; do not implement them all. The expected value comes from a concrete, testable boundary and a disciplined null interpretation, not from a claimed new universal algorithm.
